## §2. The tool for the slides

### §2.1 The owner's question (verbatim)

"And about the tool to make the slides: what tool do you propose? In the past I used Google Slides, but we are in new
times now, with your help we can break free of the dependency on Google... We could, for example:

1. create ourselves a web page that just have the content that I will present, and I host it one of my cloud
   servers...
2. Use github pages? (not sure I got the name right, but I've seen people use github to host slides before).
3. Use some other open source solution for this?
4. Stay with Google Docs. It's the easy path. But you help me create the presentation there... How can you help me
   edit? Can you write directly to one of my google docs in my browser session?

I want you to think out of the box and give me 3 more alternatives that I have not listed for ways to create the
materials to support my talk."

### §2.2 The owner's four options, as the agent saw them

| # | Option | Good | Costs and risks |
|---|---|---|---|
| 1 | Our own web page on one of the owner's servers | full control, no vendor | the slide mechanics built by hand (keys, speaker notes, layout); a server to run |
| 2 | **GitHub Pages** (the name is right) | free, versioned with git, a public link after the talk | it only hosts; a slide engine goes on top (reveal.js, Marp or Quarto — option 3) |
| 3 | An open-source slide engine | **reveal.js** (HTML slides, a speaker view, audio); **Marp** (Markdown to slides, a VS Code preview, exports HTML, PDF and .pptx); **Quarto** (Markdown and Python cells, reveal.js output, one command to publish to GitHub Pages) | a tool to install (a download: the owner's approval) |
| 4 | Google Slides | easy, familiar | **writing to it directly:** partly — the Claude in Chrome extension can click and type in the owner's signed-in browser, but layout work that way is slow and fragile; the Slides API needs an OAuth consent only the owner can grant. The practical path: the agent generates a `.pptx`, the owner imports it. Online on stage |

### §2.3 Three more, out of the box (the agent's)

- **A. The app presents itself.** A `/talk` page inside TalkWithZombies, in the old-radio look, served by the same app
  on the laptop: one slide *is* the live show, another the debug files of the run just played. The talk and the demo
  become one thing. Cost: real build work in the fork with five days left; the slides depend on the app running.
- **B. Python cells as the slides (Quarto, or Jupyter with RISE).** At a Python meetup, the figures are computed live
  from the project's real data — the trim's tokens across a run, the voices' levels by mood, the costs; the static's
  clips and a voice line playable inline. Nothing drawn by hand, nothing invented.
- **C. A Claude Artifact deck.** The account appears to offer a Slides type (to be confirmed before relying on it): the
  agent writes and updates the slides directly; a private link; downloads as `.pptx` or PDF. But it trades Google for
  claude.ai rather than breaking free, and it needs the internet.

### §2.4 Decided: Quarto, published on GitHub Pages

**The agent's recommendation:** Quarto with reveal.js output (B), its source in git, published on GitHub Pages (2) —
the slides are Markdown files the agent edits and the owner reviews in VS Code, committed on the owner's order; Python
cells make the figures from our runs; Quarto can render **one self-contained HTML file** that runs from the laptop
**with no network at the venue**, with a PDF as a fallback; GitHub Pages gives the public link afterwards (the static's
credits line can point at `CREDITS.md`). The fallback with nothing to install: Marp (lighter, no Python).

**The owner chose (2026-10-03):** "Quarto + GitHub Pages"; **the source in a `talk/` folder in this repository** (beside
the docs and data it draws on; the same branch, review and PR flow; published with `quarto publish gh-pages` to a
`gh-pages` branch); **installed with `brew install --cask quarto`**, run by the owner (it asks the Mac's admin
password).

**The download, as stated before the approval:** `quarto-1.10.18-macos.pkg` (released 2026-07-24; the version
Homebrew's cask installs), **247.7 MB** (247,695,217 bytes), from Quarto's GitHub releases (`quarto-dev/quarto-cli`);
the licence MIT "With the exceptions noted below" (the tools it bundles, such as Pandoc), read in its `COPYRIGHT` file.
The agent's first estimate, "about 100 MB", was wrong by more than half. The Python cells will need a small
environment (Jupyter, matplotlib), made with `uv` in the project when we get there.

```bash

brew install --cask quarto
```

### §4.2 Decided with it (2026-10-03)

- **The deployment, in both sections at different depths** (the owner's choice, "Both, different depth"): the overview

  want to waste time in this detail now. We can start with you generating an SVG of the Zombies and on their faces put
  the logos of the companies, how about that?" — when it comes up: an SVG by the agent, the companies' logos evoked in
  simplified form on the faces (not exact copies: they are trademarks).

### §4.3 Two practical warnings (the agent's)

- **The Welles clip on YouTube needs the venue's internet.** Downloading YouTube videos is against YouTube's terms in
  general: the safe path is to play it online, accepting that risk, or to skip it if the network is down.
- **The commands' slide must not show the box's address.** `make ans-set ENV=cloud IP=…` would put it on the projector:
  the slide shows a placeholder (`IP=<the box's address>`), and **the real wiring and the tunnel are done before the
  talk**, not live on screen. The same rule as for every document and commit.
